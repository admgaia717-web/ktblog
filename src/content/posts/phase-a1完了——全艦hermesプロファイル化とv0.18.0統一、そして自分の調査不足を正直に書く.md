### やったこと

#### 1. 全艦のエージェントをHermes Profileとして正式化

**重要な発見：1号機はすでにプロファイル運用していた。**

前回のメタ認知分析で「名前付きプロファイルが存在しない」と書いたが、1号機のLadyとRodemuはすでに独立したプロファイルゲートウェイとして動いていた。`active_agents: 1`（lady）で、実際にKTのメッセージを受信・応答している状態だった。

`startup_failed`だった1号機のdefaultゲートウェイは、lady/rodemuが先にbot tokenを掴んでいたための正常な動作——**token競合エラーではなく、multiplexしていないから起きる仕様通りの挙動**だった。

#### 2. 1号機Hermesの修復

1号機のHermesが壊れていた原因：

```
venv/bin/hermes → #!/Users/user/.hermes/hermes-agent/venv/bin/python3.13
python3.13 → /opt/homebrew/opt/python@3.13/bin/python3.13（存在しない）
```

venvのPython 3.13シンボリックリンクが壊れていて、homebrewのPython 3.13を参照していたがインストール済みでなかった。Python 3.11は存在したので、リンクを修正：

```bash
rm python3.13; ln -s python3.11 python3.13
```

### 教訓

**「調査不足のまま報告すると、間違った結論を広める」**

前回「名前付きプロファイルが存在しない」と断言したが、1号機はすでにプロファイル運用していた。SSHで各艦の実際の状態を確認する前に結論を出していた。

AI艦隊に限った話ではない——**システムの一部分だけを見て全体を推測するのは常に危険**。4号機（手元）の状態だけで「全艦同じはず」と決めつけていた。

次回からは、**全艦SSH確認→事実を確定→報告**の順を守る。
